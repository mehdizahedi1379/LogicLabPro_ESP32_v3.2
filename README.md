# LogicLab Pro روی ESP32

وب‌اپ شبیه‌ساز مدار منطقی (`logiclab_pro_v2.html`) به‌صورت gzip داخل فلش ESP32 قرار گرفته و با وب‌سرور داخلی سرو می‌شود.

## ساختار
```
LogicLabPro_ESP32/
├─ LogicLabPro_ESP32.ino    ← اسکچ اصلی
├─ config.h                 ← تنظیمات Wi-Fi / نام mDNS
├─ index_html.h             ← وب‌اپ فشرده‌شده (تولید خودکار)
├─ webapp/logiclab_pro_v2.html   ← فایل اصلی HTML (بدون تغییر)
└─ tools/embed_html.py      ← تبدیل HTML به index_html.h
```

## راه‌اندازی
1. پوشه را در Arduino IDE باز کنید (`LogicLabPro_ESP32.ino`).
2. در `config.h` مقدار `WIFI_SSID` و `WIFI_PASS` را دستی بنویسید. حالت Access Point حذف شده است؛ اگر اتصال برقرار نشود، ESP32 هر ۱۰ ثانیه دوباره تلاش می‌کند.
3. Board: **ESP32 Dev Module** (یا برد خودتان)، Partition: پیش‌فرض.
4. آپلود کنید و Serial Monitor را روی 115200 باز کنید.
5. آدرس نمایش‌داده‌شده (مثلاً `http://192.168.1.50`) یا `http://logiclab.local` را در مرورگر باز کنید.

نیازی به نصب کتابخانه‌ی اضافه نیست (فقط ESP32 Arduino core نسخه‌ی 2.x یا 3.x).

## نکته‌ی مهم: اینترنت سمت کلاینت
این وب‌اپ از **Tailwind CDN، Google Fonts و Gemini API** استفاده می‌کند؛ یعنی دستگاهی که صفحه را باز می‌کند (گوشی/کامپیوتر) باید اینترنت داشته باشد.
- حالت **Station** (اتصال ESP32 به مودم یا هات‌اسپات گوشی؛ تنها حالت پشتیبانی‌شده): همه‌چیز کار می‌کند.

## ویرایش وب‌اپ
بعد از تغییر `webapp/logiclab_pro_v2.html`:
```
python3 tools/embed_html.py
```
سپس اسکچ را دوباره آپلود کنید.

## Endpointها
- `/` ← وب‌اپ
- `/health` ← وضعیت (JSON)
- `/io?i=34,32u&o=2:1` ← پل I/O (خواندن ورودی‌ها / نوشتن خروجی‌ها)
- `/io/caps` ← لیست پین‌های مجاز

## پل I/O (پین‌های واقعی ESP32 در وب‌اپ)
در وب‌اپ دکمه‌ی **I/O** (بالا سمت راست) پنل پین‌ها را باز می‌کند. با «In» / «Out» کنار هر پین، قطعه‌ی
**ESP32 Pin In** (ورودی از پین واقعی) یا **ESP32 Pin Out** (خروجی روی پین واقعی) روی بوم اضافه می‌شود و مثل بقیه‌ی
قطعات سیم‌کشی می‌شود. پین، pull-up/down و معکوس‌سازی از Inspector تنظیم می‌شود.

**اتصال و تنظیمات I/O:** در پنل I/O دکمه‌ی **Connect I/O** تا ۳ بار اتصال به برد را امتحان می‌کند و نتیجه را
(موفق، یا دلیل ناموفق‌بودن: برد پاسخ نمی‌دهد / فرمور بدون پل I/O / آدرس اشتباه) هم در پنل و هم به‌صورت پیام اعلام می‌کند.
تنظیمات پنل در مرورگر ذخیره می‌شوند:
- **Board address**: خالی = همان صفحه‌ای که از ESP32 باز شده. اگر وب‌اپ را از کامپیوتر باز می‌کنید، آدرس برد را بنویسید و
  در `config.h` مقدار `IO_ALLOW_CORS` را 1 کنید (توجه: این گزینه امنیت را کم می‌کند، پیش‌فرض 0 است).
- **Auto-retry**: تلاش خودکار هر ۳ ثانیه تا وقتی آفلاین است؛ با خاموش‌کردن آن فقط با دکمه وصل می‌شود.
- **پایداری پل I/O:** پل فقط وقتی «آفلاین» می‌شود که **۲۰ ثانیه** هیچ پاسخی از برد نیاید (یعنی Wi-Fi واقعاً قطع است؛
  اگر مرورگر خودش آفلاین باشد ۵ ثانیه). خطاهای کوتاه (پاسخ کند، تلاش مجدد Wi-Fi، مشغول‌بودن برد) فقط نقطه را زرد
  می‌کنند (`ESP32 I/O (weak)`) و با تلاش مجدد هر ۰٫۲۵ ثانیه جبران می‌شوند. تایمرها در Web Worker اجرا می‌شوند تا
  در تب پس‌زمینه کند نشوند. فرمور: Wi-Fi sleep خاموش، اتصال مجدد بدون قطع اتصال در حال برقراری، و زمان انتظار HTTP کوتاه.

**انتخاب پین از Inspector:** قطعات معمولی **Toggle Switch**، **Push Button** و **LED** هم در Inspector گزینه‌ی
«ESP32 input pin» / «ESP32 output pin» دارند. با انتخاب یک پین، همان قطعه به پین واقعی وصل می‌شود
(کلید/دکمه از پین می‌خوانند، LED روی پین می‌نویسد) و نشان `GPIOxx` زیر قطعه دیده می‌شود. با گزینه‌ی «None» دوباره
فقط شبیه‌سازی می‌شود و پین آزاد می‌شود. گزینه‌های Pull و Invert هم در همان‌جا هستند.
Switch/Button بعد از وصل شدن همچنان با کلیک دستی کار می‌کنند و هر بار که سطح پین تغییر کند، از پین پیروی می‌کنند.

- پین‌های مجاز در `config.h` (`IO_PINS_IN` / `IO_PINS_OUT`) تعریف شده‌اند؛ پین‌های فلش/بوت/UART عمداً حذف‌اند.
- پین‌های 34–39 فقط ورودی‌اند و pull داخلی ندارند.
- اگر وب‌اپ به ESP32 وصل نباشد (مثلاً روی کامپیوتر باز شود)، قطعه‌ی Pin In مثل کلید قابل کلیک است و Pin Out فقط شبیه‌سازی می‌شود.
- **ایمنی:** اگر مرورگر بیش از `IO_WATCHDOG_MS` (پیش‌فرض ۱۵ ثانیه) درخواست نفرستد، خروجی‌ها LOW و آزاد می‌شوند
  (تب بسته یا در پس‌زمینه‌ی طولانی هم همین اتفاق می‌افتد).
- سرعت: وب‌اپ حدود ۱۰–۱۵ بار در ثانیه پین‌ها را همگام می‌کند؛ برای سیگنال‌های سریع‌تر (بالای چند هرتز) روی پین واقعی مناسب نیست.
- احراز هویت وجود ندارد: هر دستگاهی روی همان شبکه می‌تواند پین‌ها را تغییر دهد؛ فقط روی شبکه‌ی قابل‌اعتماد استفاده کنید.

## نام پین‌ها روی قطعات
نام همه‌ی پین‌ها داخل قطعه نوشته می‌شود: ورودی‌ها سمت چپ و خروجی‌ها سمت راست (مثلاً مالتی‌پلکسر ۸به۱:
`D0…D7` و `S0, S1, S2` ورودی و `Y` خروجی). وقتی پینی ۱ است نامش سبز می‌شود. نام عنوان قطعه (مثل MUX) بین نام پین‌ها
قرار می‌گیرد و اگر جا نباشد بالای قطعه می‌آید. در زوم کمتر از ۵۵٪ نام پین‌ها برای خوانایی پنهان می‌شوند.
